# 핵심 소품 10종 · Meshy 제작 기록

2026-10-12. 승인된 소품 카탈로그에서 개별 이미지를 추출·재생성한 뒤 Meshy image-to-3d로 제작했다. 추가 유료 재생성은 하지 않았다.

- 사용량: 10건 × 30 = **300크레딧**. 조회 잔액: **735크레딧**.
- 개별 요청 ID와 사용량: `provenance.json`.
- 이미지 제작 입력과 프롬프트: `reference-prompts.json`.
- 원본 GLB, 서비스 미리보기, 수정 Blender 파일: `models/`.
- 분리·최적화된 FBX, 텍스처, 피벗과 재질 명세: `Unreal/`.
- 실제 모델 검수 페이지: `docs/core-props-v1.html` (저장소 루트 기준).

Blender에서 크기, 방향, 폴리곤 수를 정리하고, 서랍과 수납장 내부를 직접 추가했다. 비다양체 생성물의 불안정한 부울 연산 대신 평면 분할을 사용했다. GLTF에서 가져온 회전 모드를 XYZ로 명시해 문 회전과 침대 방향이 실제로 적용되도록 했다. 언리얼 재질은 일부 소품의 과장된 금속성·노멀 강도를 낮췄으므로 Blender 검수 이미지와 광택이 다를 수 있다.

책상은 플레이 피드백에 따라 최초 100cm에서 264cm로 확장했다. 관리실 안쪽 폭 268cm에 맞춰 좌우 2cm 여유를 두고, 옆문 회전 영역 앞의 창가에 배치했다. 서랍장과 다리 두께는 보존하고 상판과 다리 사이 공간만 늘렸다. 이미지와 Meshy 원본은 최초 제작 기록이며, 수정본은 `prepared.blend`와 FBX에 저장된다. 추가 Meshy 크레딧은 사용하지 않았다.

후속 배치 수정에서는 식탁 높이를 바꾸지 않고 평면 크기만 4/3배로 늘렸으며, 의자 중심을 식탁 중심에서 130cm로 옮겼다. 객실 옷장은 양쪽 벽에 하나씩 두던 배치를 수정해 왼쪽 벽에 두 개를 나란히 붙였다. 책상 의자는 옷장 뒤쪽의 책상 아래로 넣었다. 두 옷장은 서로 다른 ID를 사용해 열림 상태를 따로 기록한다. 이 변경 역시 기존 모델 재사용으로 추가 생성 비용이 없다.

## 재현

1. `tools/prepare_core_props.py`를 Blender 백그라운드에서 실행한다. `NR_CORE_ONLY` 환경변수에 쉼표로 ID를 지정하면 부분 재처리한다.
2. `tools/build.ps1 -EngineRoot <UE 경로> -ImportCoreProps -Package`로 가져오기와 패키징을 수행한다.
3. `tools/catalog_core_props.py`로 검수판 및 비공개 URL을 제거한 제작 기록을 갱신한다.

`meshy_output/`에는 임시 다운로드 URL과 원시 응답이 있으므로 Git에서 제외한다. 이미 완료된 작업을 다시 제출하지 않는다. 새 유료 생성은 별도 사용자 승인 범위로 다룬다.

기존 DAY 1 프로토타입의 소품을 교체하고 CCTV 촬영을 위한 3층·옥상 계단을 기존 맵에 연결했다. 별도로 승인된 3층+옥상 전체 평면 재구축 완료를 뜻하지 않는다. 생성 흔적과 세부 표면은 최종 출시 전에 추가 미술 검수가 필요하다. CCTV 구성과 범위는 `docs/cctv-stack.md`에 기록했다.

## 검증 결과

- Windows Development 패키징 성공.
- `NRFeedbackTest`: 서랍과 카트리지, 냉장고·옷장 여닫기 및 체크포인트 복원 실패 0.
- `NRComplaintLogTest`: 책상 위 장부 지지면·주변 소품 간섭·상호작용 및 기존 기록 흐름 실패 0.
- `NROfficeCCTVTest`: 관리실 CCTV와 플레이어 표시 실패 0.
- `NRInvestigationTest`, `NRSmokeTest`: UV 조사와 기본 진행 실패 0.
- `runtime-desk.png`: 마지막 빌드에서 촬영하고 육안 확인한 화면.

가져오기 도구는 재질 정의에 따른 고유 이름을 사용한다. UE 5.8이 사용 중인 재질 표현식을 삭제할 때 발생했던 `IsRooted` 오류를 피하면서 재실행 시 같은 재질을 재사용한다. 전체 플레이타임과 모든 방의 미술 완성도는 이 검증에 포함하지 않는다.
