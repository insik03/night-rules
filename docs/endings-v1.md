# 최종밤 엔딩 프로토타입 v1

기준: `story-plan-v03.md`의 TRUE / RED / BLACK. 기존 DAY 1에서 최종밤으로 이어지는 **시험용 챕터**다. DAY 2~4를 구현하거나 중간 사건을 플레이한 것으로 처리하지 않는다. 첫 회차 120분 완성본이 아니며, 이 챕터의 첫 플레이 시간도 아직 사람에게 측정하지 않았다.

## 시작

- 기존 실행파일 `Builds/Windows/NightRulesPrototype.exe` 실행 → Esc → **최종밤 엔딩 테스트 · 중간 날짜 생략**.
- 또는 DAY 1 끝 화면에서 Enter.
- 바로 실행: `PlayFinalNight.cmd` 더블클릭. PowerShell에서는 `tools/play-final-night.ps1`.
- 엔딩 화면에서 Enter: 최종밤 처음부터 다시 시도. R: DAY 1 재시작.
- 문서·확인창: Esc로 닫기. 진행 기록: J. 사망: R로 직전 체크포인트.

## 첫 조사

관리실 전화로 관리자의 종료 절차와 다른 목소리의 부탁을 듣는다. 근무일지에서 조사 장소를 확인하고 자유롭게 이동한다. DAY 1에서 202호에 들어가지 않았거나 마지막 전화를 무시했더라도 모든 결말에 도달할 수 있다.

| 장소 | 행동과 결과 |
|---|---|
| 관리실 왼쪽 벽 | 반환 단자로 307호 회선의 목적을 확인. 별도 차단기로 연결·차단 |
| 105호 / 204호 / 301호 | 각 층의 재실 인원 확인: 5명 / 4명 / 5명. 확인만으로 대피 완료가 되지는 않음 |
| 203호 | 민서 부재 확인 |
| 3층 샤워실 | 첫 조사로 민서 위치 확인, 다시 조작하면 걸림을 풀고 구조 |
| 옥상 계단실 바깥 정비함 | 3층 비상문 해제공구 확보 |
| 3층 서쪽 비상문 옆 | 공구로 봉인 해제. 문을 직접 열고 다시 조사해 대피 인계 시작 |
| 302호 책상 | 도윤의 마지막 점검 쪽지. 전화 수신과 반환 발신이 다른 행동이라는 단서 |
| 307호 문 앞 / 방 안 | 문 앞 바닥의 열쇠 확보(안전) → 방 안 회선함 자물쇠 개방 → 관리실 단자 확인 후 반환선 연결 또는 분리. 입실·문 닫기는 별도 선택 |
| 관리실 PC | 실제 재실·구조·대피·봉인·회선 상태를 열람. 미해결 상태의 종료 보고에는 명시적 확인 필요 |

## 결말 조건 (스포일러)

### TRUE — 열린 문

세 층의 재실 확인과 민서 구조 → 옥상 공구 확보 → 3층 서쪽 비상문 봉인 해제 → 문 열기 → 문을 다시 조사해 대피 인계 → 비상문 근처에서 각 층과 민서의 응답 확인 → **15/15명 확인 후** 문을 통과 → 바깥 계단참의 ‘외부 계단으로 내려가기’ 조작.

구조·재실 확인·대피는 서로 다른 상태다. 일부 인원만 확인하고 인계를 시작해도 나중에 돌아가 남은 사람을 확인하고 추가로 인계할 수 있다. 모든 인원의 응답 뒤 플레이어도 탈출해야 완료된다.

### RED — 새 총무

관리실 반환 단자 확인 → 307호 문 앞 바닥의 열쇠 확보 → 방 안 회선함 자물쇠 개방 및 연결 → 관리실의 307호 차단기가 켜진 상태 유지 → 307호 안으로 들어가 **문이 완전히 닫힌 뒤** 책상 전화로 직접 발신.

전화 수신, 열쇠 획득, 방 입실만으로는 결말이 발동하지 않는다. 연결을 분리하거나 문을 열고 나오는 선택은 마지막 발신 전까지 가능하다.

결정됨(2026-10-14): RED는 DAY 1 `final_call` 청취 기록에 따라 장면을 나눈다. 받았다면 관리자의 첫 인수인계와 그날 들었던 말이 돌아오고, 받지 않았다면 다섯 번째 벨 직전에 상대가 받으며 한 번도 듣지 못한 말을 한다. 기록 없는 직행·체크포인트는 미응답 장면을 쓴다. 두 장면 모두 플레이어가 ‘이번에는 문 좀 열어주세요.’라고 말한다. 공통 엔딩 카드의 마지막 줄은 “이번이 몇 번째인지, 나는 모른다.”다. DAY 1의 307 발신자가 이전 희생자였을 가능성은 열어 둔다.

DAY 1 두 번째 전화(`second_call`)의 민서 목소리는 사칭 존재다. 청취 기록이 있는 경우에만 최종밤 민서 위치 확인·구조·대기 대화에서 “전화요? 저 관리실에 전화한 적 없는데요. 202호 문도 안 열었어요.”를 듣는다.

### BLACK — 아무 일 없었습니다

비상문을 봉인한 상태로 307호 회선 차단 → PC에서 남은 미해결 항목 확인 → Enter로 종료 보고 제출 → 현관 양문을 열고 밖으로 나가기.

또는 비상문을 열었지만 대피가 끝나기 전에 외부 계단으로 떠나는 선택을 확인한 경우. 미확인 인원을 사망자로 단정하지 않으며 경고창에서 Esc로 돌아갈 수 있다. 보고 제출 뒤에도 회선을 복원하거나 봉인을 풀면 승인이 취소되어 조사를 계속할 수 있다.

## 공포 / 재시도

- 비상문 개방 뒤 3층 복도 안으로 돌아갈 때만 최종 추격이 준비된다. 의자 끄는 소리와 짧은 전조 후 시작한다.
- 추격은 3층 직선 복도에 한정된다. 옥상 공구 조사나 좁은 계단에서 갑자기 시작하지 않는다.
- 잡히면 사망한다. 죽음은 엔딩으로 계산하지 않는다. R로 추격 직전 상태를 복원한다.
- 첫날의 전화·202호 잠금·추격 사건이 최종밤에서 다시 실행되지 않도록 분리했다.

## 이번 구현의 범위

기존 건물과 소품을 재사용한 진행 검증용 구현이다. 새 Meshy 생성과 크레딧 사용은 없다. 정비함·회선함·열쇠표는 기존 메시를 이용한 임시 소품이다.

대피는 **화면 밖 계단의 발소리와 자막 응답**으로 표현한다. 15명이 실제로 걸어 나가는 군중 AI/캐릭터 연출은 아직 없다. 외부 계단참까지는 직접 이동하고, 계단 아래 이동은 암전 전환으로 처리한다. 옥외 계단 전체를 걸어서 내려가는 구현은 아니다.

엔딩에는 실제 상호작용 조건, 짧은 종료 연출, 결과 화면과 재시도가 있다. 새 대사의 한국어 음성 녹음은 아직 없고 자막과 기존 효과음만 사용한다. 저장은 기존의 실행 중 체크포인트 방식이며 게임 종료 후 이어하기는 제공하지 않는다.

## 검증 방법

- `NRFinaleTest`: 세 결말과 두 BLACK 경로, 취소·번복, 상태 복원, 추격·사망, DAY 1 선택 보존을 생산 코드의 상호작용으로 검사. 위치·시간은 테스트용으로 설정하므로 처음부터 끝까지 걸은 플레이나 플레이타임 측정은 아니다.
- `NRFinaleWalkTest`: 주요 소품의 실제 시선 충돌·조사 거리와 W 입력으로 비상문을 통과하는 동선 검사.
- 기존 DAY 1, 202호 우회, 근무일지 방침, CCTV 매핑 회귀 검사.
- `capture_endings.ps1`: 패키징된 게임에서 명시적으로 준비한 장면을 촬영한다. AI 생성 시안이 아니다. 결과는 `endings-v1.html`.

2026-10-13 검증 결과: 에디터 및 Windows 패키징 성공. 최종 빌드의 `NRFinaleTest` 35항목, `NRFinaleWalkTest` 11항목 통과(실제 W 이동과 Enter 확인 포함). 기존 `NRDemoTest`, `NRChoice202Test`, `NRInvestigationPlanTest`, `NRComplaintLogTest`, `NRCCTVStackTest`도 모두 failures=0. 캡처 검토에서 발견한 책장 위 전화·쪽지 배치를 책상 상판으로 수정하고 관련 검사를 재실행했다. 처음부터 끝까지의 사람 플레이 및 소요시간 검증은 별도로 남아 있다.

2026-10-14 변경 검증: `tools/verify_story_regressions.py`, `tools/validate_project.py`, `git diff --check` 통과. 수정 C++ 4개 파일을 MSVC `/Zs /Y- /std:c++20`로 문법 검사했다. `NRFinaleTest`에 RED 수신·미수신·기록 없음, 최종밤 전환·체크포인트 보존, 문 앞 바닥 열쇠·안전한 획득 검사를 추가했다. `NRChoice202Test`에는 민서 대화 6경로의 청취 조건과 체크포인트 복원 검사를 추가했다. 새 엔진 통합 검사는 빌드 후 실행해야 한다. 엔진 빌드·UHT·음성 생성·임포트·커밋은 실행하지 않았다.

음성 작업 인계: 기존 비청취 대사와 `second_call`·`final_call`은 그대로다. 새 청취 대사 키는 DAY 1의 `minseo_second_call`, `resident_203_second_call`, `resident_203_safe_second_call`(민서 F1)이다. 최종밤의 새 키는 `final_minseo_located_second_call`, `final_minseo_rescued_second_call`, `final_minseo_waiting_second_call`이다. 기존 생성기는 DAY 1의 고정 대화 키만 더빙하므로 새 키를 민서 F1로 생성 대상에 포함해야 한다. 최종밤은 기존부터 음성이 없으며, RED의 `final_scene_RED`·`final_scene_RED_unheard`와 민서 최종밤 키는 더빙을 추가할 경우 사용할 원문 키다. `voices.json`·WAV·음성 에셋·생성기는 수정하지 않았다.
