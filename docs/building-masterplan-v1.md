## 최신 수정 — 현재 좁은 복도와 방 유지

사용자는 첫 조감도가 고시원의 좁은 복도·방 콘셉트와 다르다고 지적했고, 현재 게임의 복도는 괜찮다고 명시했다. 따라서 **기존 복도 폭·방 크기·문 간격·천장 높이를 보존**하고, 그 구조를 기준으로 3층과 옥상을 확장한다. 기존 공간을 넓히거나 다른 건물 평면으로 교체하지 않는다.

첫 building-overview.png는 공간 비례가 부적절해 제작 기준에서 제외한다(rejected_scale). rooftop-eye-level.png도 승인되지 않은 분위기 후보일 뿐, 건물 면적·옥상 크기의 근거가 아니다. 다음 이미지는 실제 게임 캡처와 현재 평면을 참조해야 한다. 계단·현재 복도의 눈높이 이미지를 먼저 확인하고, 조감도 때문에 공간 비례를 바꾸지 않는다.

## 사용자가 정한 제작 원칙

- 실내 1·2·3층과 4층 높이의 옥상을 한 건물로 구상한다. 옥상은 추가 입주층이 아니다.
- 옥상에는 실제 생활 공간인 빨래 건조 구역을 두고 탐색과 사건에도 활용한다.
- **모든 맵 구역 및 소품은 제작 전 이미지를 사용자에게 먼저 보여준다.** 전체 분위기 이미지 확인을 개별 소품 승인으로 간주하지 않는다.
- 확인된 디자인을 기준으로 모델링한다. 이미지 수정 → 확인 → Meshy/Blender 제작 → Unreal 적용 순서다. 확인 전 유료 3D 생성이나 기존 맵 교체를 하지 않는다.
- 이름은 해담고시원. 관리실은 1층 현관 앞, 매우 작은 공간, 정면 아래 절반 벽/위 절반 유리, 연속된 옆벽의 출입문이다. 의자 뒤 한 명이 누울 자리만 두며 별도 숙소를 새로 만들지 않는다.

## 구상과 현재 구현의 구분

현재 런타임은 1·2층 중심의 프로토타입이다. 이 문서는 3층·옥상을 포함한 목표 설계이며 구현 완료를 뜻하지 않는다. 기존 level-layout.md의 일부 폭·방 개수 수치는 과거 초안이다. NRGame.h/NRGame.cpp의 현행 구조가 기준이다: 주 입주실 복도 명목 폭 130cm(벽 두께에 따라 유효 폭은 더 작음), 방 피치 230cm, 방 깊이 300cm, 층고 320cm, 실내 천장 약 260cm, 층당 12개 방 배치. 새 3층은 이 규격을 이어받으며 307호 등 사건 공간의 변경은 별도 이미지 확인을 거친다. 기존 사건의 104·105·202·203·301·307호와 이름·통화 관계를 유지한다.

이번 단계의 목표는 전체 건물의 공간 역할, 연결, 소품 범위와 사건 사용을 정하는 것이다. 현재 평면·게임 캡처 확인 → 기존 규격을 유지한 층별 콘셉트/확장 평면 → 구역·소품별 승인 이미지 → 모델링 순서로 진행한다. 아래 층별 역할은 사건 배분 제안이며, 기존 주방·공용 공간을 임의로 이전하거나 철거하는 지시가 아니다.

## 연결과 크기 초안

- 건물 바닥 면적과 긴 형태는 현재 맵 외곽을 기준으로 한다. 처음 제안했던 20×12m 재설계는 철회한다. 옥상도 해당 외곽과 계단 위치에서 시작한다.
- 주계단은 1층부터 옥상까지 실제로 연속된다. 계단참, 천장 구멍, 외벽, 난간, 계단 하부를 함께 설계한다.
- 뒤쪽 비상계단은 지상부터 옥상까지의 물리적 연결을 계획한다. 초기에는 특정 출입문의 잠금과 정비 덮개로 접근 상태를 제어한다. 과거 화재의 핵심은 3층에서 이 경로에 접근할 수 없었던 사실이다.
- 각 생활층의 복도와 공용공간에 한 개 이상의 우회 연결을 둔다. 침실은 주민 사생활 때문에 기본적으로 통과 동선이 아니다.
- 주 입주실 복도는 현재 명목 폭 130cm와 문 배치를 유지한다. 1.6~1.8m 확대안과 2.2m 교행부 신설안은 철회한다. 추격은 기존 좁은 복도의 압박감, 기존 연결 통로와 계단, 귀신 속도·출현 위치로 조정한다. 통과 문제를 확인한 특정 접합부만 별도 검토하며 전체 복도를 넓히지 않는다.
- 외벽의 창문에는 실제 외부 시야를 제공한다. 화장실·실내 경계벽·계단 접합부까지 닫힌 구조인지 점검한다.
- 옥상은 현재 건물 외곽 안에서 주계단 문 → 건조 구역 → 설비 외곽 → 주계단 문으로 돌아오는 동선과 뒤편 계단 분기를 검토한다. 옥상 이미지를 맞추기 위해 건물이나 복도를 키우지 않는다. 천은 시야 일부만 가리고 이동 충돌벽으로 사용하지 않는다.
- 옥상 추격은 탈출 경로를 먼저 확보했을 때만 검토한다. 막힌 옥상에 들여보내 출입문을 잠근 즉사 연출은 만들지 않는다. 기존 추격 횟수 목표를 늘리지 않고 후반 추격 경로의 후보로 사용한다.

## 옥상의 사건 활용 제안 — 기존 스토리에 추가 검토

1. **일상으로 익히기:** 세탁기 진동이나 비에 젖기 전에 빨래를 걷어달라는 부탁. 건조대·설비·두 계단 위치를 자연스럽게 익힌다. 빨래를 널고 걷는 상호작용은 지정 위치 한 세트로 제한하고 별도 세탁 시뮬레이션은 만들지 않는다.
2. **공격 없는 목격:** 바람에 움직이는 이불 뒤에 사람 윤곽이 잠깐 보인다. 확인하면 없으며 이 장면 자체로 추격을 시작하지 않는다. 선택 목격이다.
3. **판단에 쓰이는 UV:** 옛 비상문 손잡이/정비 덮개 주변의 지워진 점검 표시를 확인한다. 옛 도면·나사 교체 흔적과 비교해 어느 접근로를 먼저 열지 결정한다. UV가 없더라도 조사와 기록으로 같은 핵심 사실을 찾을 수 있다.
4. **후반에 회수:** 미리 확인한 뒤편 계단으로 3층 비상문의 바깥쪽에 접근한다. 옥상 자체가 진실을 푸는 마법의 장소가 아니라, 기존 스토리의 막힌 구조 경로를 실제로 여는 데 도움을 주는 공간이다.

옥상 통로 개방이 기존 TRUE 엔딩의 조건을 자동으로 대체하지 않는다. 민서 구조·남은 입주민 대피와 원래 통로 개방을 유지한다. 옥상에서 놓친 선택 목격 때문에 엔딩이 봉쇄되지 않는다.

| 순서 | 이미지 묶음 | 확인할 사항 |

Meshy는 소품·설비 외형에 활용하고, Blender에서 크기/원점/가동부/충돌/최적화를 정리한다. 계단·외벽·개구부 등 맞물려야 하는 구조는 이미지 승인 후 Blender로 규격 제작한다. 글자·방 번호는 별도 원본으로 작성한다. 기존 CC0 소품도 재사용 배치 이미지를 보여준 뒤 확정한다.

## 완료 확인 기준

- 1층에서 3층 및 옥상까지 실제 걸어서 연결되고 뒤편 경로의 잠금/개방 상태가 일치한다.
- 계단 주변 빈틈, 벽 관통, 부유 소품, 문 회전 간섭이 없다.
- 닫힌 문·열린 서랍·빨래 천이 추격 경로를 부당하게 막지 않는다.
- 공용 공간과 옥상에는 생활 목적과 최소 한 가지 조사/사건 목적이 있다.
- 플레이어 시점/CCTV 시점/추격 중 시야에서 재질·조명·성능을 확인한다.
- 최종 모델링 이전에 해당 구역과 해당 소품의 이미지 확인 기록을 남긴다.
